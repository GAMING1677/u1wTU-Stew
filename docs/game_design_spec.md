# ゲームデザイン仕様書 (Game Design Specification)

> [!NOTE]
> このドキュメントは、現在のコードベース (`Assets/Scripts` 以下) の解析に基づいて作成された逆設計書です。実装されている機能を反映しています。

## 1. 基本情報
*   **プロジェクト名**: Approval Monster (承認欲求モンスター / u1wTU-Stew)
*   **ジャンル**: ソーシャルメディア運営シミュレーション × デッキ構築型ローグライク
*   **プラットフォーム**: PC / Mobile (Unity)
*   **画面**: 横画面 (1920x1080想定)

## 2. ゲーム概要
プレイヤーはSNSアカウント（あるいはインフルエンサー）を育成・管理し、カードを使って「投稿」を行い、承認欲求（インプレッション・フォロワー）を満たしていくゲーム。
各ステージには「ノルマ（目標インプレッション数）」が設定されており、限られたターン数内でノルマを達成することを目指す。

## 3. コアゲームループ
1.  **ステージ開始**: ステージごとに設定されたノルマと制限ターン数が提示される。
2.  **ターン進行**:
    *   **ドロー**: 山札からカードを引く。
    *   **アクション**: 手札のカードをプレイして、インプレッションやフォロワーを獲得する。
        *   カードの使用にはコスト（主にメンタル）が必要。
        *   カードには様々な効果（即時獲得、バフ、デバフ、特殊状態）がある。
    *   **ターン終了**: 手札を捨て、メンタルの自然回復や継続効果の処理を行う。
3.  **ステージクリア判定**:
    *   **クリア**: 制限ターン内に目標インプレッション（Quota）に到達する。
    *   **ゲームオーバー**: メンタルが0になる、または制限ターン内にノルマ未達成。
4.  **報酬**: 新しいカードの獲得（ドラフト）、デッキの強化。
5.  **次のステージへ**: 難易度の上がった次ステージへ進む。

## 4. リソース (Resources)
ゲーム内で管理される主要なパラメータ。

*   **Impression (インプレッション)**:
    *   いわゆる「スコア」。`long`型で管理され、上限は 999,999,999。
    *   ステージごとのノルマ達成に必要。
    *   カードの効果によって直接獲得したり、ターン経過で獲得したりする。
*   **Follower (フォロワー)**:
    *   インプレッション獲得効率に影響する「倍率」パラメータ。
    *   フォロワーが多いほど、1回の投稿（カードプレイ）で得られるインプレッションが増加する。
*   **Mental (メンタル)**:
    *   いわゆる「HP」兼「コスト」。
    *   多くのカードは使用時にメンタルを消費する。
    *   メンタルが0以下になると活動不能（ゲームオーバー）になる可能性がある。
    *   ターン終了時に回復する場合もある。
*   **Motivation (やる気)**:
    *   カード使用コスト（アクションポイント）。
    *   各ターン開始時に回復し、カードプレイで消費する。
*   **Flaming (炎上度)**:
    *   **Seeds (火種)**: 特定のカード効果で蓄積する。
    *   **Flaming Level (炎上レベル)**: 炎上が発生した際のダメージ量。
    *   **On Fire (炎上状態)**: 炎上判定に失敗すると発生。ターン終了時に炎上レベル分のメンタルダメージを受ける。
*   **Infection (感染度)**:
    *   **Zombie Deck** モード専用リソース（0〜100%）。
    *   特定のカード使用で上昇/下降する。
    *   **Penalty**: ターン終了時に `現在のフォロワー数 × 感染率(%)` 分のフォロワーを失う。
    *   **Reset**: ステージ設定により、デッキのリシャッフル時に一定割合（例：50%）低下する。

## 5. ゲームシステム (Game System)
*   **制限事項**:
    *   **ターン制限**: ステージごとに設定されたターン数以内にノルマを達成する必要がある。
    *   **カードプレイ回数制限**: 1ターンにつき最大 **10回** までカードをプレイ可能。
    *   **スコアカンスト**: インプレッションの最大値は **999,999,999**。
*   **ドラフト (Draft)**:
    *   ステージクリア後やカード効果で、ランダムに提示された3枚のカードから1枚を選んでデッキに追加する。
    *   **Tier Probability**: 現在のインプレッション数に応じて、提示されるカードのレアリティ（Common/Rare/Epic）の出現確率が変動する。インプレッションが高いほど、高レアリティが出やすくなる。

## 6. カードシステム (Card System)
*   **デッキ (Deck)**:
    *   プレイヤーが構築するカードの束。
    *   ドローパイル（山札）とディスカードパイル（捨て札）の概念がある。
*   **カードパラメータ**:
    *   **Cost**: 使用に必要なメンタル量 / やる気消費量。
    *   **Effect**:
        *   インプレッション獲得
        *   フォロワー獲得
        *   メンタル回復/消費
        *   バフ/デバフ付与（次のターンの効果倍増など）
        *   特殊効果（手札を捨てる、引くなど）
    *   **Rarity**: Common, Rare, Epic などのレアリティ区分。
*   **Monster Cards (モンスターカード)**:
    *   **Type A (King)**: 感染度をリセットし、現在感染度に応じたインプレッション/フォロワーを獲得。
    *   **Type B (Duplicate)**: 感染度に応じた確率で、このカードを山札に複製する。
    *   **Type C (Transform)**: 感染度に応じた確率で、手札の他のカードをこのカードに変質させる。

## 7. ステージ・進行システム
*   **Stage (ステージ)**:
    *   難易度の区切り。
    *   **Quota**: ノルマとなるインプレッション数。
    *   **MaxTurn**: ステージの制限ターン数。
    *   **Monster Mode**:
        *   メンタルが一定値以下（デフォルト30%）になると発動。
        *   BGMが変化し、専用のモンスターカードドラフトが発生する。
        *   インプレッション獲得倍率やペナルティが変化する。
*   **Score Attack**:
    *   特定のステージではスコア上限を目指す「エンドレスモード」や「スコアアタックモード」が存在する。ハイスコアは保存される。

## 8. UI / 演出
*   **SNS風インターフェース**: タイムラインやプロフィール画面を模したUI。
*   **キャラクターリアクション**: プレイヤーの行動や状況（メンタル低下、ノルマ達成など）に応じてキャラクターのアニメーションや表情が変化する。
*   **演出**:
    *   カード使用時のエフェクト。
    *   インプレッション増加時の数値演出。

## 9. 実装済み重要クラス (Script Reference)
*   `GameManager`: ゲーム全体のステートマシン（ターン管理、勝敗判定、モンスターモード制御）。
*   `ResourceManager`: 各種リソース（Impression, Follower, Mental, Flaming, Infection）のデータ管理。
*   `CardData`: カード個別のデータを定義するScriptableObject。
*   `StageData`: ステージ設定を定義するScriptableObject。
*   `UIManager`: UI全体の統括。
*   `DeckManager`: デッキ操作（ドロー、シャッフル、廃棄）の管理。
*   `DraftManager`: カードドラフトの生成と確率計算。
*   `SaveDataManager`: ステージクリア状況、ハイスコアの永続化管理。
*   `StageManager`: ステージリスト管理と遷移制御。
